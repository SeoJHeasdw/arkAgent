## 다른 저장소에서 진행 중

세 엔진을 계약에 맞추는 일은 각 엔진 저장소의 세션이 한다. assets는 전부, music과 tts는
1단계(검사 통과)까지가 범위다. 그 보고에 계약 수정 제안이 오면 계약 문서와 검사 도구를 함께
고친다.

## 다음 작업

1. **관문 CLI `ark`.** 프론티어가 Bash로 부르는 표면이다. 출력은 문장이 아니라 짧은 줄이다.
   - `ark engines` — 등록된 엔진마다 한 줄(꺼짐 / 쉼 / 실행 중인 작업).
   - `ark recipes <엔진>` — 레시피 이름과 필수 입력.
   - `ark submit <엔진> <레시피> --params <JSON>` — `<엔진>:<작업 ID>`를 돌려준다. 다른 엔진이
     일하는 중이면 넣지 않고 그 사실을 알린다(장비 하나에서 한 번에 한 엔진). `--when-idle`은
     빌 때까지 기다렸다 넣고, `--wait`는 끝날 때까지 기다려 결과를 낸다.
   - `ark status <작업>` — 한 줄.
   - `ark result <작업>` — 상태, 산출물 경로, 확인할 곳의 개수와 위에서 몇 개, 작업 폴더.
   - `ark cancel <작업>`.
   - 엔진 주소는 `~/.arkagent/config.yaml`의 `engines`에서 읽고 기본값은 계약 문서의 포트다.
2. **측정 기록.** 작업이 끝나면 엔진 · 레시피 · 단계별 시간 · 최대 메모리 · 실패 분류 · 장비 이름을
   `~/.arkagent/ledger.jsonl`에 한 줄로 남긴다. 장비를 바꿀 근거가 여기에 쌓인다.
3. **프론티어 비용 측정.** Claude Code 세션 기록에서 턴 수와 턴당 맥락 크기를 재는 도구.
   2026-10-14에 임시 스크립트로 잰 값은 tts 엔진 저장소 27세션 5,243턴, 턴당 약 33만 토큰,
   엔진 명령을 실행한 턴 39%다. 관문을 쓰기 전과 후를 같은 방법으로 비교한다.
4. **MCP 표면.** CLI와 같은 코어를 MCP 도구로도 낸다. 도구 수는 적게 둔다.
5. **첫 작업.** 강의 CH01의 한 레슨 음성을 관문으로 만들고 프론티어 턴 수를 잰다.
